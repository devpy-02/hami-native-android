# ابزار حامی — بازسازی بومی اندروید

این مخزن برای تبدیل تدریجی برنامهٔ React/TypeScript به برنامهٔ Native Android با Kotlin و Jetpack Compose ساخته شده است. پوشهٔ `reference-react/` فقط مرجع بررسی رفتار نسخهٔ قبلی است و در APK اجرا نمی‌شود.

## ساخت APK با GitHub Actions

1. کل محتویات این پوشه را در یک مخزن GitHub قرار دهید.
2. مخزن را روی شاخهٔ `main` یا `master` پوش کنید.
3. از بخش **Actions**، گردش‌کار **Android APK** را باز کنید.
4. پس از موفقیت، از بخش Artifacts فایل `hami-tools-debug-apk` را دریافت کنید؛ فایل درون آن `app-debug.apk` است.

همچنین می‌توان گردش‌کار را از تب Actions با گزینهٔ **Run workflow** اجرا کرد.

## وضعیت فعلی

- نقطهٔ ورود برنامه Native و مبتنی بر Compose است؛ WebView حذف شده است.
- صفحهٔ اصلی به صفحات اولیهٔ Kotlin برای کالاها، فروش، فروش سریع، فاکتورها، تاریخچه و مشتریان متصل می‌شود.
- دفتر حساب مشتری اکنون فاکتور فروش/برگشت فروش را ثبت می‌کند؛ ثبت دریافت از مشتری و نمایش گردش حساب نیز در صفحهٔ مشتریان اضافه شده است.
- گزارش بدهی مشتریان به صفحهٔ اصلی اضافه شده و مجموع طلب مثبت، مانده‌های بستانکاری، تعداد مشتریان بدهکار و فیلتر/جست‌وجوی مشتریان را از مانده‌های ثبت‌شده نشان می‌دهد.
- در فرم فاکتور رسمی، مشتری فعال را می‌توان از فهرست جست‌وجو و انتخاب کرد و شناسهٔ مشتری در فاکتور ذخیره می‌شود؛ فیلدهای نام طرف حساب، شماره تماس و نشانی در فاکتورهای رسمی و سریع وجود دارند و اطلاعات تماس مشتری انتخاب‌شده خودکار پر می‌شود. این اطلاعات در دیتابیس هم ذخیره می‌شوند؛ مهاجرت دیتابیس به نسخهٔ ۵ دو ستون تماس و نشانی را بدون حذف فاکتورهای قبلی اضافه می‌کند.
- نوع «فروش عمده» به انواع فاکتور سریع و رسمی اضافه شده است. در فاکتور رسمی، فروش عمده مانند فروش موجودی را کم می‌کند و در حساب مشتری ثبت می‌شود؛ در فاکتور سریع، هیچ‌یک از انواع فاکتور موجودی یا حساب مشتری را تغییر نمی‌دهند.
- لایهٔ Room شامل مهاجرت صریح تا نسخهٔ ۳، جداول مشتریان/دفتر حساب/ثبت وقایع و مخازن اولیه است؛ هنوز باید با مدل‌ها و جریان‌های کامل React تطبیق داده شود.
- این نسخه هنوز بازسازی کامل قابلیت‌های React نیست و تا اجرای موفق CI، ساخت APK تأییدشده محسوب نمی‌شود.
- قبل از استفادهٔ واقعی باید مهاجرت دیتابیس، پشتیبان‌گیری/بازیابی، محاسبات مالی و تمام جریان‌های فروش آزمایش شوند. گزارش بدهی فعلاً از ماندهٔ ذخیره‌شدهٔ مشتری استفاده می‌کند؛ صحت آن وابسته به ثبت درست همهٔ فاکتورها و دریافت‌هاست. از وارد کردن اطلاعات واقعی تا گذراندن این آزمایش‌ها خودداری کنید.

## ساختار

- `android/`: پروژهٔ بومی Kotlin/Compose
- `reference-react/`: نسخهٔ React اصلی، صرفاً برای مرجع مهاجرت
- `.github/workflows/android.yml`: ساخت خودکار APK در GitHub Actions
